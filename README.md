# longtail-rl

**Straggler-aware rollout generation for RL post-training of reasoning models.**

In RL fine-tuning (GRPO, PPO), most wall-clock time goes to *generating* rollouts, not training.
Reasoning traces have a heavy-tailed length distribution: most finish in a few hundred tokens, a few
run to the token limit. When the trainer waits for the whole batch, the slowest 1% of sequences set
the step time, and the GPU decodes a shrinking, memory-bound batch for most of the step.

This project measures that cost and then removes it.

## Scheduling modes

| Mode | Behavior |
|---|---|
| `barrier` | Submit the whole batch, wait for every sequence (how most RL frameworks work today) |
| `refill` | Keep the engine full: start a new GRPO group whenever a group's worth of slots frees up. A step is emitted once `prompts_per_step` complete groups exist; long sequences carry over into later steps with bounded, measured staleness |

## Metrics (per step, comparable across modes)

| Metric | Meaning |
|---|---|
| `wall_s` | time to deliver one batch of complete groups to the trainer |
| `tokens_per_s` | output tokens delivered / wall_s |
| `slot_occupancy` | time-averaged sequences in flight / capacity (1.0 = engine always full) |
| `tail_wait_fraction` | share of the step spent after 90% of its sequences were done |
| `staleness_mean/max` | policy versions between submitting and delivering a sequence (barrier = 0) |
| `len_p50/p99/max`, `truncation_rate`, `mean_reward` | rollout distribution; checks refill doesn't bias toward short answers |

## Running on a cluster (SGE / BU SCC)

```bash
# login node, once
uv venv --python 3.12 && source .venv/bin/activate
uv pip install -e ".[dev]"
pytest                                 # CPU-only: metrics, reward, queue, and both schedulers on a fake LLM
python scripts/prefetch.py             # download weights + dataset before the GPU job

# GPU: one job runs a whole experiment queue
qsub -v PLAN=experiments/smoke.toml jobs/queue.qsub   # ~5 min sanity check
qsub jobs/queue.qsub                                   # experiments/commit2.toml: barrier vs refill
qstat -u $USER
```

Each queue writes `results/queue-<timestamp>-<jobid>/`:

```
plan.toml  status.json  queue.log  comparison.md
<run>/  config.json  env.json  run.log  steps.jsonl  traces.jsonl  summary.json
```

Runs execute as separate processes (GPU memory fully released between runs; one crash doesn't stop
the queue). If the job hits its time limit, `qsub -v RESUME=results/queue-... jobs/queue.qsub`
re-runs only the unfinished runs. Plans are validated before any GPU time is spent: a typo in a
key fails immediately.

To add an experiment, add a `[[run]]` block to a plan. Any `RolloutConfig` field can be set.

## Engine telemetry and speculative decoding

Every run samples vLLM's own metrics once a second (`telemetry.jsonl`) and adds per-step
preemptions, KV-cache usage, running/waiting sequences, generated tokens/s and, when
speculative decoding is on, vLLM's measured acceptance to `steps.jsonl` and
`comparison.md`. Speculative decoding is configured with `spec_method` (e.g. `"ngram"`),
`spec_k`, `spec_min_n`, `spec_max_n`, passed straight to vLLM's `speculative_config`.

## Sibling-draft speculative decoding (offline study)

GRPO samples G completions per prompt, and siblings reuse a lot of phrasing at different
offsets. A sequence can draft its next k tokens by matching its last n tokens against a
sibling's text, then verify all k in one forward pass: prompt-lookup speculation with
siblings as an extra draft source, and no draft model.

For temperature sampling with top_p = 1, the chance that a recorded sample matches a fixed
draft token equals the chance speculative sampling accepts it (both are p(x)). So replaying
recorded rollouts gives an unbiased estimate of acceptance with no changes to vLLM:

```bash
qsub -v PLAN=experiments/collect_tokens.toml jobs/queue.qsub          # record 1,024 rollouts at 16k
python -m longtail.specsim results/queue-.../collect-16k/tokens.jsonl  # CPU, ~1 min
```

The simulator replays each barrier batch step by step (siblings only expose text they had
generated by that engine step) and compares draft sources (`self` = vLLM's n-gram method,
`sibling`, `both`) under two policies (`always`, or only in the `tail` when few sequences
are still running). It reports tokens per step, acceptance, and makespan reduction: how
much sooner the batch's last sequence finishes.

## Sibling drafter in vLLM

`longtail.drafter.SiblingProposer` runs the same self + sibling rule inside vLLM through the
`custom_class` speculative method (vLLM's V1 runner, `runner_v2 = 0`). Request ids are tagged
`g{group}-r{n}` so the drafter knows which sequences are siblings; finished siblings stay
available to stragglers until their group is done. `draft_gate = N` turns drafting off while
more than N sequences are decoding, so the bulk phase pays no verification cost. The drafter
is tested to reproduce `longtail.specsim` exactly on the same token streams.

```bash
qsub -l h_rt=00:30:00 -v PLAN=experiments/drafter_smoke.toml jobs/queue.qsub
qsub -l h_rt=06:00:00 -v PLAN=experiments/drafter_16k.toml jobs/queue.qsub
```
